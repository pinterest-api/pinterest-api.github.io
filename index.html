Pinterest API Review: Access, Limits and What It Does

The Pinterest API is five products under one name, and only one of them lets you start today without an app review. Here is which one, and what the others ask for.

Five products wearing one name

Pinterest's developer platform presents a single API, but the use cases it lists are effectively separate products with separate access paths. Conversions covers sending purchase and signup data back to Pinterest for optimisation and reporting. Content covers building apps that create and manage organic Pins and boards on a user's behalf. Ads covers campaign management, targeting setup and performance reporting. Catalogs, marketed as the Pinterest API for Shopping, handles product feeds and shopping ads. Analytics covers pulling content and ad data into your own warehouse. Deciding which of the five you need is the first real decision, because the approval requirements differ sharply between them and picking the wrong entry point costs weeks.

The one door that opens without approval

Here is the detail buried in Pinterest's help documentation and absent from most write-ups. The Conversions API does not require an application or a valid app ID. Anyone with a Pinterest Business account can start calling the POST send conversions endpoint, as long as they have generated a token from the Conversions page in Ads Manager. That is genuinely unusual and it means an advertiser can ship server-side tracking without waiting on a developer review. The limit is equally explicit: having a Business account does not automatically grant access to the wider Pinterest API. So Conversions is a fast lane, not a back door into content or ads endpoints, and planning a roadmap on the assumption that one implies the other will go badly.

What a conversions integration actually involves

Pinterest offers two routes. A third-party partner integration works if you already use one of its partner platforms, and a direct integration gives the most control but needs developer time. The timeline Pinterest quotes is honest and wide: as little as a few hours, or as long as a few weeks, depending which route you take. Four things decide whether the integration is any good. Pass data in real time, meaning under an hour, or real-time optimisation and attribution do not work. Pass the event_id parameter if you also run the Pinterest Tag or a mobile measurement partner, or your conversions get double-counted. Fire a test event and read the response codes back. Then watch Event Quality Score and aim for Good, because a working integration and a useful one are different things.

Getting onto the wider platform

Everything outside Conversions starts at the developer account setup flow, which you reach with a Pinterest business login rather than a personal one. Pinterest maintains an official quickstart repository on GitHub with runnable examples, which is a faster way into the request shapes than reading reference docs cold. Read the developer guidelines and the developer and API terms before you build, because what an app is permitted to do with user content is the part that gets integrations rejected rather than anything technical. There is a community forum for the questions docs do not answer. Pinterest has also announced an MCP server as on the way, aimed at letting agents call the platform directly, though at the time of the snapshot behind this page it was previewed rather than shipped.

When the API is not the answer

A lot of people searching for this API want something simpler than an integration: get a week of Pins scheduled, keep Pinterest in step with the other channels, and see which posts worked. What you actually get

Conversions with no app ID

A Pinterest Business account plus a token generated in Ads Manager is enough to call the send conversions endpoint. No application, no review, no waiting on a developer approval.

Web, app and offline events

The Conversions API accepts web conversions, in-app conversions and in-store or offline conversions, sent server to server rather than through a browser tag.

Deduplication is on you

If you also run the Pinterest Tag or a mobile measurement partner, pass event_id so the same conversion is not counted twice. Post-dedup numbers show in Events Overview.

An official quickstart repo

Pinterest publishes runnable examples on GitHub under its own organisation, which gets you to a working request faster than the reference documentation alone does.

Shipping a conversions integration

  1. Generate the token in Ads Manager
    Open the Conversions page in Ads Manager with a Pinterest Business account and create a token. No app registration is involved for this product specifically.
  2. Choose direct or partner
    A partner integration is faster if you already use one of Pinterest's partner platforms. A direct integration gives more control and needs developer time. Pinterest quotes hours to weeks.
  3. Send event_id with everything
    If the Pinterest Tag or a measurement partner is also firing, event_id is what stops the same conversion being counted twice. Check the deduplication view in Events Overview afterwards.
  4. Fire a test event and read the codes
    Validate in Events Manager rather than assuming. Response codes come back per request, and Event Quality Score tells you whether the data you are sending is good enough to optimise on.

FAQ

Do I need app approval to use the Pinterest API?

It depends which product. The Conversions API explicitly does not require an application or a valid app ID: a Pinterest Business account plus a token generated on the Conversions page in Ads Manager is enough. The wider API, covering content, ads and catalogs, goes through the developer account setup flow instead.

What can the Pinterest API actually do?

Pinterest groups it into five use cases: tracking conversions, creating and managing organic content such as Pins and boards, building and managing ad campaigns, managing product catalogs through the API for Shopping, and pulling content and ad analytics into your own data warehouse or analytics tools.

How long does a Conversions API integration take?

Pinterest's own estimate is as little as a few hours or as long as a few weeks, depending on whether you go through a partner platform you already use or build a direct server-to-server integration. The direct route gives the most control over the process and needs developer involvement.

How do I avoid double-counting conversions?

Pass the event_id parameter on every event if you are also running the Pinterest Tag or a mobile measurement partner. Post-deduplication conversions appear on the Events Overview page in Ads Manager, which is where you confirm the deduplication is actually working rather than assuming it.

Is there a Pinterest MCP server?

Pinterest has announced one as on the way, with its own information page on the developer site. At the time of the snapshot behind this page it was previewed rather than generally available, so check the developer platform directly before planning an agent integration around it.

I just want to schedule Pins. Do I need any of this?

No. Building a scheduler on the content endpoints means writing OAuth, a queue, retries and an analytics rollup before the first Pin goes out. Supapush already handles scheduling, queueing, a calendar and analytics across ten networks, so the API only becomes necessary for tracking or catalog work.
